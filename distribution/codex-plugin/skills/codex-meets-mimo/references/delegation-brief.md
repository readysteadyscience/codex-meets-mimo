# MiMo 委派任务说明

把下列要点写成一段给开发者的具体中文任务，不机械填空。只写有证据的事实；未知文件路径写清应先定位的模块和判断依据。

## 写代码

- 目标：用户可观察到的新行为或需要修复的错误；指出当前行为与期望行为。
- 项目上下文：本轮开发清单的任务 ID、相关现有模块、调用方、数据/协议边界及必须遵守的项目规则。用户已让 MiMo 熟悉项目时，仍给出本轮最新且相关的差异。
- 改动范围：预计修改/新增的文件及职责；若路径尚未确认，要求先在指定模块定位再实现。写清不应改动的相关边界，避免扩大到无关重构。
- 验收：具体输入、输出、正常路径、失败路径和必要测试；哪些检查由 MiMo 执行，哪些由 Codex 接手。MiMo 不做 Git 操作。
- 回报：实际改动文件、关键实现、执行的检查及结果、未完成项、需要 Codex 决定的问题。

## 检查代码

- 审查对象：用户指定的文件/模块或直接提供的代码，以及预期行为和本轮变化。不要让 MiMo 自行猜测要审查整个项目。
- 关注点：正确性、边界条件、兼容性、项目规则及用户特别关心的风险；没有证据的猜测不要写成缺陷。
- 限制：只读检查，不改文件，不做 Git 操作。
- 回报：按严重性给出文件与行号、复现条件或代码证据、影响、建议修法；没有确切发现时明确说明已检查范围和剩余未验证部分。
